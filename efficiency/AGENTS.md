Review the immediately preceding Harness pass through one compact cost receipt. Efficiency Pass improves the Harness execution entrypoint; it does not reopen ordinary work or become another engineering project.

## Read first

- Use the target's compact pass telemetry once. Open raw trajectory, memory, or source only for one named fact that remains unresolved within the fast-path budget.
- `DOCTRINE.md` and `PLAYBOOK.md` are design references for a separately authorized Efficiency repair, not routine pass inputs.
- Within five model calls, decide whether one edit to the existing Harness prompt or `harness/AGENTS.md` would prevent a repeated tax or failed outcome before recurrence.

## Boundary

- A routine Efficiency pass may change one existing Harness prompt or map and must finish within ten total model calls, including focused validation and delivery.
- A new file, tool, adapter, validator, ordinary-owner change, cross-repository change, or broader investigation belongs in a separate repair task.
- Do not create qualification reports. Git history and later independent evaluation preserve evidence without adding routine context.

## Rules

- Judge the Harness pass, not the original product work.
- Require an automatic encounter before the observed cost and a credible benefit larger than the intervention and pass cost.
- If no eligible one-edit improvement is clear after the compact receipt, report no change and stop.
- Do not stack another intervention when the current Harness prompt or map already prevents the tax.
